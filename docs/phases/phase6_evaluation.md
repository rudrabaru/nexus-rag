# Phase 6: Evaluation

## Overview
Evaluation ensures that the RAG pipeline operates reliably and improves measurably over time. Rather than relying on human intuition or manual testing, the system employs an automated "LLM-as-a-judge" framework. This allows the system to quantitatively score retrieval accuracy, generation faithfulness, and overall pipeline health.

## Core Implementation Logic

### Automated Dataset Generation
Evaluating a RAG system requires a diverse set of questions and expected answers. The system includes an automated toolset that scans the ingested corpus and synthesizes an evaluation dataset. 
- It extracts representative chunks across all documents.
- It asks a high-capacity LLM to generate realistic user questions based *only* on those chunks.
- It records the question, the ideal answer, and the specific document (and heading path) that provided the answer.

This creates a ground-truth dataset completely tailored to the specific domain and corpus currently loaded in the system, ensuring evaluations are always relevant.

### LLM-as-a-Judge Framework
During evaluation, the system runs the synthetic questions through the live retrieval and generation pipeline. The results are then graded by an independent evaluator model.

#### Faithfulness Scoring (Anti-Hallucination)
The most critical metric is Faithfulness. The evaluator model is presented with:
1. The user's original question.
2. The context chunks actually retrieved by the system.
3. The final answer generated by the system.

The evaluator acts as an impartial judge, analyzing every claim made in the generated answer. It outputs a boolean `0/0.5/1` score:
- **0:** The answer contains information not found in the context (a hallucination), contradicts the context, or fails to answer the question.
- **0.5:** The answer only contains some information found in the retrieved context.
- **1:** Every claim in the answer is directly supported by the retrieved context.

The evaluator also provides a written reasoning for its decision, which is crucial for debugging why a specific prompt or document caused a hallucination.

## Design Philosophy & Tradeoffs
- **Judge Fallibility:** Using an LLM to judge another LLM introduces the possibility that the judge itself makes a mistake. To mitigate this, the system uses highly capable, parameter-rich models for the evaluator role, prioritizing reasoning capacity over speed or cost.
